## 1. Goal

Build a law library that M4 and M5 can search and cite. It holds the Consumer Rights Act 2015 (Part 1, Chapter 2), the relevant sections of the Consumer Credit Act 1974, and the FCA's CONC and DISP chapters. It stores every point-in-time version with its validity dates, plus contextual headers, embeddings and a manifest. The data lives in Postgres with pgvector and keyword search, behind a store interface with an in-memory fake, and comes with a command-line inspector.

M3 adds no agent behaviour. `retrieve()`, reranking, the relevance gate and the citation checker are M4; research tools for lawyers are M5. M3 gives them what they need: stable library IDs, validity dates, original text for quotes, and two raw searches (vector and keyword), each filtered by `as_of`.

## 2. Done when

From design section 14:

> Ingestion for the Consumer Rights Act 2015, relevant CCA 1974 sections, and the FCA's CONC and DISP chapters, with point-in-time versions, contextual headers, embeddings and manifest; library inspector in the console.

As checkable conditions for this plan (section 3 explains each change):

1. `docker compose up -d db` starts PostgreSQL 18 with pgvector 0.8.7, and `uv run alembic upgrade head` creates `law_chunks` as in section 6.3.
2. `uv run alteram law status` lists `cra-2015` and `cca-1974` with chunk counts, one embedding model, and no manifest mismatch.
3. Point-in-time versions are stored with validity dates. `uv run alteram law search "<words from CCA s.75>" --as-of <date> --keyword-only`, run on either side of an amendment date, returns the version in force on each date.
4. Every chunk has a contextual header. `uv run alteram law show <id>` prints the original text and the header separately.
5. A second `uv run alteram law ingest <source> --dry-run` reports 0 header calls, 0 embedding calls and $0.00.
6. `law/manifest.json` is committed, with source URLs, raw-file hashes, version dates, chunk counts, unapplied effects, header model and prompt version, and embedding model and dimension.
7. FCA CONC and DISP are either ingested the same way, or deferred by Gabriel with the reason recorded in `docs/SETUP_LOG.md` (see 3.2).
8. `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest` pass locally and in GitHub Actions. Database tests run in CI against a Postgres service (step 10).

## 3. Conflicts with the design and changes to it

### 3.1 The inspector cannot be "in the console" in M3

`AGENTS.md` and the 29 October decision order v1 as M3, M4, M5, then M2. The console is M2, so it doesn't exist when M3 ends. **This plan builds a command-line inspector instead** (`alteram law show`, `search` and `status`, step 16) and moves the console's library view to M2. The CLI and the console read the same store interface, so nothing built in M3 needs to change for M2. Gabriel to confirm (decision D1 in section 10).

### 3.2 FCA content can't be fetched by a script without consent

See section 4.3. The FCA steps (18 to 20) are a separate track gated on Gabriel's decision D2. The statute track does not wait for it.

### 3.3 Migrations are run by hand in M3

Design 8.3 runs migrations from `docker compose up`, which needs a backend container. That arrives with the API in M2. In M3, `uv run alembic upgrade head` is run by hand.

### 3.4 Built-in full-text search first; BM25 is decided in M4

Section 4.1 has the facts. M3 builds keyword search on Postgres's built-in full-text search (`tsvector`, `websearch_to_tsquery`, `ts_rank_cd`), behind the `search_keyword` method that design 9.2 already asks for. Every hit records its backend. M4 can then add a `pg_textsearch` backend and compare recall@k on the retrieval gold set before choosing. This is the design's own fallback, taken first because the BM25 extension needs a custom database image.

### 6.2 Library IDs and validity

- **Library ID** = the legislation.gov.uk URI path of the provision plus its start date: `<type>/<year>/<number>/section/<s>[/<sub>]/<in_force_from>`, e.g. `ukpga/2015/15/section/9/1/2015-10-01`. A provision split into parts adds `~<n>`: `.../section/22/9/2015-10-01~2`. A validator checks that the date in the ID equals `in_force_from`. FCA IDs: `fca/<SOURCEBOOK>/<rule>/<in_force_from>`, e.g. `fca/DISP/2.8.2R/2025-01-01`.
- **Validity is half-open.** In force on `as_of` when `in_force_from <= as_of` and (`in_force_to` is null or `as_of < in_force_to`). Step 04 must establish from the fixtures whether legislation.gov.uk's `RestrictEndDate` is inclusive or exclusive, and convert to this rule.
- **Holdout rows are never returned by a search.** No filter can include them. `get(id)` still returns them, because M4's checker must be able to say "exists but held out".
- **Citations use `text_original` only.** `text_contextual` is header + blank line + original, and is used only for embedding and keyword search.

### 6.3 The `law_chunks` table (migration `0001_law_chunks`, step 09)

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE law_chunks (
    id               text PRIMARY KEY,
    source           text NOT NULL,                 -- key in law/sources.toml, e.g. cra-2015
    source_url       text NOT NULL,
    doc_type         text NOT NULL CHECK (doc_type IN ('statute','regulation','decision','case_law','guidance')),
    authority_tier   text NOT NULL CHECK (authority_tier IN ('statute','regulation','decision','case_law','guidance')),
    jurisdiction     text NOT NULL,                 -- uk, england_wales, ...
    extent           text,                          -- raw RestrictExtent, e.g. E+W+S+N.I.
    heading_path     text[] NOT NULL,               -- Act > Part > Chapter > section
    in_force_from    date NOT NULL,
    in_force_to      date,                          -- exclusive; NULL if current
    text_original    text NOT NULL,
    text_contextual  text,                          -- NULL until headers exist
    embedding        vector(1024),
    embedding_model  text,
    topics           text[] NOT NULL DEFAULT '{}',
    holdout          boolean NOT NULL DEFAULT false,
    licence          text NOT NULL,
    attribution      text NOT NULL,
    ingested_at      timestamptz NOT NULL DEFAULT now(),
    source_sha256    text NOT NULL,                 -- raw file the chunk came from
    chunk_sha256     text NOT NULL,                 -- heading_path + text_original
    search_tsv       tsvector GENERATED ALWAYS AS
                     (to_tsvector('english', coalesce(text_contextual, text_original))) STORED,
    CHECK (in_force_to IS NULL OR in_force_to > in_force_from),
    CHECK ((embedding IS NULL) = (embedding_model IS NULL))
);
CREATE INDEX law_chunks_embedding_idx ON law_chunks USING hnsw (embedding vector_cosine_ops);
CREATE INDEX law_chunks_search_idx    ON law_chunks USING gin (search_tsv);
CREATE INDEX law_chunks_validity_idx  ON law_chunks (in_force_from, in_force_to);
CREATE INDEX law_chunks_source_idx    ON law_chunks (source);
```

This is design 6.4 plus `extent`, `embedding_model`, `chunk_sha256` and `search_tsv`. The dimension is fixed at 1024 (the `voyage-4-large` default). Another dimension needs a new migration, and the manifest check stops a mismatched model first.

### 6.4 The store interface (design 9.2)

```python
class LawStore(Protocol):
    backend: str  # "memory" or "postgres"

    def upsert(
        self,
        chunks: Sequence[LawChunk],
        embeddings: Mapping[str, Sequence[float]],
        embedding_model: str | None,
    ) -> int: ...
    def get(self, chunk_id: str) -> StoredChunk | None: ...
    def ids(self, source: str) -> set[str]: ...
    def remove(self, chunk_ids: Iterable[str]) -> int: ...
    def search_vector(
        self,
        embedding: Sequence[float],
        as_of: date,
        k: int,
        filters: SearchFilters = SearchFilters(),
    ) -> list[SearchHit]: ...
    def search_keyword(
        self, query: str, as_of: date, k: int, filters: SearchFilters = SearchFilters()
    ) -> list[SearchHit]: ...
    def counts(self) -> dict[str, int]: ...  # chunks per source
    def embedding_models(self) -> set[str]: ...
```

`SearchHit` carries `chunk_id`, `score`, `rank` and `backend` (`memory`, `postgres_fts`, `pgvector`). One contract test suite runs against `MemoryStore` always, and against `PostgresStore` when a test database is set.

### 6.5 Ingestion (design 6.6)

| Load | `alteram law load <source> [--dry-run] [--budget USD]` | Voyage, Postgres | `law_chunks` rows; `law/manifest.json` |
| All | `alteram law ingest <source> [...]` | all | all of the above |

- **Fetch:** per section listed in `sources.toml`: get the current XML, read its `hasVersion` dates, then get each dated version. `enacted` and `prospective` are skipped. Requests are sequential, at least 1 second apart (well under 1,500 per 5 minutes), with `User-Agent: alteram/<version> (+<ALTERAM_HTTP_CONTACT>)`. Existing files are skipped unless `--refresh`.
- **Build:** parse every version, merge into validity spans, split provisions over 4,000 characters at paragraph boundaries, and attach metadata and topics from `sources.toml`. Commentary is never part of the text. Report skipped elements and unapplied effects.
- **Headers:** Haiku writes 2–3 sentences per chunk from `prompts/contextual_header.md`. The document context is the source's text in force on the chunk's `in_force_from`, capped at 180,000 characters so a prompt stays under 100,000 tokens even at 2 characters per token. The document goes in a cached content block. The cache key is model + prompt sha256 + document sha256 + chunk sha256.
- **Load:** embed `text_contextual` (`input_type="document"`) only for new or changed chunks, upsert, remove the source's stale IDs, and write the manifest entry. Before any embedding, check the configured model and dimension against the manifest and the store.
- **Costs:** priced from `pricing.py`. `--dry-run` makes no calls and prints the calls and worst-case cost. `--budget` (default $5, separate from `ALTERAM_RUN_BUDGET_USD`; D7) stops before a call that could exceed it.
